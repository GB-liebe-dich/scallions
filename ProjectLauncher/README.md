# Project Launcher（项目启动器）

Project Launcher 是一款面向 Windows 的 Qt 项目工作环境启动器。它把一个项目需要打开的软件、命令、脚本、文件夹和网页整理为可重复执行的启动方案，适合开发、测试、演示、归档等需要一键恢复工作现场的场景。

![ProjectLauncher 主界面](docs/images/主界面.png) 

## 主要功能

- 使用启动方案集中管理不同项目，每个方案可包含开发、测试、归档等多个模式。
- 支持应用程序、CMD、PowerShell、文件、文件夹、URL 和延时七种启动项。
- 支持启用或禁用、复制、单项删除、批量删除、拖拽排序、跨模式分配和单项运行。
- 按列表顺序异步执行，等待进程时不会阻塞主界面。
- 支持启动前延时、启动后延时、等待启动、等待结束、管理员运行和已运行时跳过。
- 应用程序统一使用“程序路径 + 打开目标 + 启动参数 + 可选工作目录”，不区分 VS Code、Qt Creator、Keil 等软件类型。
- 选择应用程序或 Windows 快捷方式时，可自动同步程序名称和原始图标。
- 支持通用参数模板、变量插入和实时参数预览。
- 可为“启动方案 + 模式”创建桌面快捷方式，直接运行指定工作流。
- 提供置顶、紧凑的单行进度卡片，仅显示当前启动项和整体进度。
- 内置完全离线的项目图标生成器，支持名称缩写、关键词图形、渐变配色、自定义图片及 PNG/ICO 导出。
- 每个项目独立保存配置，并记录最近一次和历史运行日志。

## 核心概念

| 层级 | 作用 | 示例 |
| --- | --- | --- |
| 启动方案 | 表示一个项目或一套完整工作环境 | 项目启动器、嵌入式项目、测试环境 |
| 模式 | 表示同一项目的不同启动组合 | 开发、测试、归档 |
| 启动项 | 表示按顺序执行的一个动作 | 启动 VS Code、执行脚本、打开项目目录 |

同一个启动项可以分配给多个模式。它在这些模式中共享同一份配置，修改名称、路径或参数后会同步更新。仅从当前模式删除该启动项，不会删除其他模式中仍在使用的同一启动项。

## 快速开始

1. 点击顶部“新建方案”。
2. 输入方案名称，并按需设置项目目录。
3. 选择文字缩写或关键词图形作为项目图标，也可以导入自定义图片。
4. 进入需要配置的模式，点击“添加启动项”。
5. 选择启动项类型并填写相应属性。
6. 拖动列表行调整执行顺序，使用属性区上方的模式按钮分配所属模式。
7. 点击“保存”写入配置。
8. 点击“启动”执行当前模式。

如需从桌面直接运行当前方案和模式，点击顶部“创建桌面快捷方式”。

## 启动项类型

| 类型 | 主要配置 | 用途 |
| --- | --- | --- |
| 应用程序 | 程序路径、打开目标、启动参数、工作目录 | 启动任意 EXE、COM、BAT、CMD 或快捷方式所指向的程序 |
| CMD | 命令内容、工作目录、是否保留窗口 | 通过 `cmd.exe /C` 或 `cmd.exe /K` 执行命令 |
| PowerShell | 命令内容、工作目录 | 通过 `powershell.exe -NoProfile -Command` 执行命令或脚本 |
| 文件 | 打开目标 | 使用 Windows 默认程序打开文件 |
| 文件夹 | 打开目标 | 使用资源管理器打开目录 |
| URL | 打开目标 | 使用默认浏览器打开网页 |
| 延时 | 延时时间 | 在启动流程中插入独立等待步骤 |

普通启动项默认执行完成后等待 `1000 ms` 再继续下一项，可在属性区单独修改。延时启动项只使用自己的“延时时间”，不会再叠加普通启动项的启动后延时。

## 应用程序配置

应用程序类型不绑定任何具体软件，打开不同 IDE 或工具时使用相同配置方式。

| 设置 | 是否必填 | 说明 |
| --- | --- | --- |
| 程序路径 | 是 | 实际需要运行的程序或命令文件 |
| 打开目标 | 否 | 交给该程序打开的文件、目录或工程，可自动追加到参数末尾 |
| 启动参数/命令 | 否 | 传递给程序的额外命令行参数，也可使用变量模板 |
| 参数预览 | 只读 | 实时显示变量展开、参数分组后的等效命令行 |
| 工作目录 | 否 | 进程的起始目录，主要用于命令、脚本和相对路径 |

### 选择程序或快捷方式

- 程序选择窗口支持 EXE、COM、BAT、CMD 和 LNK。
- 选择程序后会自动同步应用程序名称和图标。
- 选择 `.lnk` 快捷方式后，程序会读取它的真实目标、启动参数和原始图标，再使用真实目标启动，因此列表图标不会带快捷方式箭头。
- 工作目录不会根据程序路径或快捷方式自动填写。只有所运行的程序、命令或脚本依赖相对路径时，才需要手动设置。

## 参数模板与变量

程序路径、打开目标、启动参数和工作目录都支持变量。点击启动参数右侧的 `{}` 按钮可以直接插入变量。

| 变量 | 展开内容 |
| --- | --- |
| `${TARGET}` | 当前启动项的“打开目标” |
| `${WORKDIR}` | 当前启动项的“工作目录” |
| `${PROGRAM}` | 当前启动项的“程序路径” |
| `${PROJECT_DIR}` | 当前方案设置的项目目录 |
| `${PROJECT_NAME}` | 当前方案名称 |
| `${MODE_NAME}` | 当前模式名称 |
| `${APP_DIR}` | Project Launcher 程序所在目录 |

变量名称严格区分大小写。例如 `${TARGET}` 有效，`${target}` 会被识别为未知变量并导致该启动项失败。

### 打开目标的追加规则

- 启动参数中没有 `${TARGET}`：非空“打开目标”会自动作为最后一个参数追加。
- 启动参数中包含 `${TARGET}`：目标只在模板指定的位置展开，不会再次追加。
- 可以多次使用 `${TARGET}`，每一处都会展开。
- 打开目标为空时，不会额外生成空参数。

### 参数分组

启动参数支持单引号和双引号分组。路径或参数值包含空格时，应将整个值放在一对引号内：

```text
--workspace "${TARGET}" --name "${PROJECT_NAME}"
```

`--workspace`、`-data` 这类参数名本身不需要引号；只有包含空格的参数值需要分组。例如：

```text
-data "${TARGET}"
```

参数预览会按照实际传递效果显示：不需要分组的普通参数不加引号，包含空格、制表符或双引号的单个参数会显示为带双引号的形式。输入程序路径、打开目标、启动参数或工作目录时，预览会立即同步更新。

### 常用示例

直接让 VS Code 打开一个目录：

```text
程序路径：D:\Program Files\Microsoft VS Code\Code.exe
打开目标：D:\Workspace\Demo
启动参数：（留空）
```

等效参数预览：

```text
"D:\Program Files\Microsoft VS Code\Code.exe" D:\Workspace\Demo
```

把目标放到指定参数之后：

```text
启动参数：-data "${TARGET}"
```

结合项目目录使用相对位置：

```text
程序路径：${PROJECT_DIR}\tools\MyTool.exe
打开目标：${PROJECT_DIR}\workspace
启动参数：--workspace "${TARGET}" --project "${PROJECT_NAME}"
工作目录：${PROJECT_DIR}
```

如果参数引号未闭合，或仍存在未知的 `${变量}`，启动前会把该项标记为失败并将原因写入日志，后续启动项仍会继续执行。

## 启动控制

| 选项 | 行为 |
| --- | --- |
| 等待程序启动 | 系统确认进程已成功启动后，再继续下一项 |
| 等待程序结束 | 程序退出后再继续，并依据退出状态和退出码判断结果 |
| 管理员运行 | 通过 Windows UAC 以管理员权限启动 |
| 程序已经运行时跳过 | 检测到同名程序正在运行时，不重复启动 |
| CMD 执行后保持窗口 | 使用 `cmd.exe /K`；关闭时使用默认的 `cmd.exe /C` |
| 启动前延时 | 执行当前项之前等待指定毫秒数 |
| 启动后延时 | 当前项执行完成之后等待指定毫秒数 |

PowerShell 使用 `-NoProfile`，表示启动时不加载用户配置脚本，减少个人环境差异；`-Command` 表示后面的内容作为 PowerShell 命令执行。这两个参数由程序自动提供，无需在命令输入框中重复填写。

已确认启动且不要求“等待程序结束”的应用会独立于启动器继续运行。关闭进度卡片或退出 Project Launcher，不会连带关闭这些已打开的软件。

## 启动项管理

- 拖动表格行可以调整当前模式中的执行顺序。
- 右键启动项可以执行复制、删除、单项运行等操作。
- 点击属性区上方的模式按钮，可以把同一启动项分配到多个模式或从某个模式移除。
- 按住 `Ctrl` 可选择不连续的多行，按住 `Shift` 可选择连续范围，然后点击“批量删除”。
- 批量删除只移除当前模式中选中的行；其他模式仍引用的共享启动项会继续保留。
- 删除前会显示一次确认提示。删除后仍需点击“保存”才会写入配置文件。

## 项目目录与模式

项目目录是整个方案的统一路径基准，主要用于 `${PROJECT_DIR}`，不会自动扫描、构建或修改该目录中的工程。

典型用途：

- 将配置交给其他电脑使用时，只修改一次项目目录。
- 在多个启动项中统一引用工程、脚本、工具或输出目录。
- 避免在程序路径、目标和参数中重复填写相同的绝对路径。

项目右键菜单中的“设置项目目录”和新建方案窗口中的“项目目录”修改的是同一项配置。

模式用于表达同一项目的不同工作流。例如：

- 开发：编辑器、终端、调试工具。
- 测试：测试脚本、日志目录、浏览器页面。
- 归档：构建产物目录、版本记录或备份脚本。

## 桌面快捷方式与进度卡片

选择方案和模式后，点击“创建桌面快捷方式”会生成一个直接运行该工作流的 Windows 快捷方式。其命令行形式为：

```text
ProjectLauncher.exe --project "项目ID" --mode "模式ID"
```

执行规则：

- 从主界面点击“启动”：流程结束后只处理进度卡片，主界面保持打开。
- 从桌面快捷方式启动且全部成功：结果显示 3 秒后缓慢渐隐，并退出启动器本身。
- 从桌面快捷方式启动且存在失败：进度卡片保持显示，用户点击后再按渐隐方式退出。
- 进度卡片始终置顶，位于屏幕中间偏上，只显示当前正在执行的一项。
- 可在“设置”中控制“显示启动进度窗口”和“完成后关闭提示窗”。

## 项目图标

项目图标完全在本地生成，不需要联网或云端服务。新建方案时可以：

- 使用项目名称缩写生成渐变图标。
- 从 Qt、芯片、终端、波形、数据库、代码、AI、云平台、相机、安全、工具等关键词图形中选择。
- 切换不同的预设图形和配色组合。
- 导入 ICO、PNG、JPG、JPEG 或 BMP 自定义图片。

项目右键菜单中的“项目图标”可以继续更换预设、恢复自动生成、选择自定义图标或导出 PNG/ICO。每个项目只保留一个当前自动图标缓存，重新生成时会替换该项目的旧缓存图标。

## 配置导入导出与数据目录

顶部工具栏提供“导入”和“导出”：

- 导出：将当前项目配置保存为独立 JSON 文件，便于备份或迁移。
- 导入：从 JSON 文件加入一个项目配置。
- 导入或修改后，建议点击“保存”确认写入。

所有运行数据默认位于 Project Launcher 程序目录：

```text
config/
├── settings.json
└── projects/
    └── 项目名称__project_xxxxxxxxxxxx.json

logs/
├── last-run.log
└── run-YYYYMMDD-HHmmss-zzz.log

cache/
└── icons/
    └── 当前项目图标.ico
```

- `settings.json` 保存程序级设置和最近选择状态。
- `config/projects` 中每个方案使用一个包含项目名称和 ID 的独立 JSON 文件。
- `last-run.log` 保存最近一次执行日志。
- 历史日志最多保留 99 份，多余的旧日志会自动清理。
- “设置 → 打开配置目录”可以快速打开配置位置。
- “设置 → 查看最后一次运行日志”可以直接查看最近一次运行结果。

当前版本只使用当前配置格式，不迁移或兼容旧版本项目配置。升级或替换程序前，请先导出需要保留的项目。

## 常见问题

### 为什么没有填写参数，打开目标仍会传给程序？

这是默认行为。启动参数中没有 `${TARGET}` 时，程序会自动把非空“打开目标”追加到参数末尾。需要控制目标位置时，在启动参数中显式使用 `${TARGET}`。

### 为什么工作目录是空的？

工作目录是可选高级设置，不会根据程序路径、打开目标或快捷方式自动填写。普通桌面应用通常可以留空；依赖相对路径的脚本、命令或工具才需要设置。

### 为什么参数预览给某些值加了双引号？

双引号用于把包含空格的内容作为一个完整参数传递。参数名一般不加引号，路径或文本值包含空格时才需要加引号。预览显示的是等效传递形式，不会把引号作为普通字符传给程序。

### CMD 和 PowerShell 为什么会自动出现额外参数？

CMD 需要 `/C` 执行后退出，或 `/K` 执行后保留窗口；PowerShell 需要 `-NoProfile -Command` 以干净环境执行输入的命令。这些是启动外壳所需的固定参数，不是额外的用户命令。

### 为什么启动项数量不为零，但表格中看不到？

先确认当前选中的模式是否正确。启动项按模式显示，同一项目的开发、测试和归档模式可以包含不同列表。也可切换一次模式重新刷新当前列表。

### 为什么关闭提示窗口后，已打开的软件没有关闭？

这是预期行为。对于不等待结束的应用，启动器只确认它已成功启动，之后该程序会独立运行。

### 修改后为什么重启没有保留？

界面中的新增、删除、排序和属性修改需要点击顶部“保存”写入磁盘。关闭程序前请确认已保存。

## 使用注意事项

- 当前版本主要面向 Windows；快捷方式、UAC、进程检测和原生图标读取依赖 Windows。
- 配置文件包含本机路径。迁移到其他电脑后，应检查程序路径、项目目录、打开目标和工作目录。
- “等待程序结束”适合命令、脚本或短时任务，不适合需要长期保持运行的编辑器，除非确实希望它关闭后才继续。
- “程序已经运行时跳过”按可执行文件名判断；同名但路径不同的程序可能被视为同一个程序。
- 管理员运行会显示 Windows UAC 提示。
- 未保存的删除和修改不会写入配置文件。
